Interactive Journey — enhanced team construction
Team Construction | three decisions per turn
01

Dispatch shape

Parallel by default. Add a round only when one answer must exist before the next question can be asked.

Example
“any spending spikes? what are the drivers?”

Causal — the spike window must exist before drivers can be read against it.

Naive parallel: spend returns a spike in 2025-05, modeling returns drivers from 2024-09. Two halves that don’t connect.

02

Team size

Minimal fetches. Maximal finds. Open, senior-level questions deliberately invert the minimum-set rule.

Example
“what’s the FICO?” → 1 specialist

Named metric, owning column, one fetch.

“any model opportunities?” → 4+

Names no metric and no table. Its value is in what the team finds, so each specialist gets a different hypothesis to test — and a checked non-finding is a result.

03

General specialist review

Server-enforced, not model-chosen. On every ≥2-specialist turn, the team is checked for coherence before the answer ships.

Example
The 2025-05 vs 2024-09 mismatch, caught

Review sees both payloads, spots the windows don’t line up, and re-runs modeling alone anchored to 2025-05 — not a whole re-plan.

Its phase-1 knowledge points are dropped first, so the corrected run doesn’t leave two contradictory anchors in memory.

One question, three decisions: what shape, how many, and who checks the result.
